## 2026-11-02 — Pipeline Map interactive #3: follow a batch

- **Built:** pure `findBatch(network, name)`, which returns every pipe the batch is in, the volume in each, and the total, plus `nextBatchInSegment` and `batchSummary`. The map has `followedBatch` / `defaultFollowedBatch` / `onFollowBatchChange`. To follow a batch you can click its band, press `B` on a focused pipe (it cycles through that pipe's batches, then stops), or use the table, where each batch is a toggle button. Escape order: tooltip → batch → trace → selection. In the demo data, B-1041 now straddles Station B.
- **Remember: identity across collections.** A batch has no id of its own in our model. Its `name` *is* its identity, and the same name in two pipes is one batch in two places. That's why the guide says to map your backend's per-part ids to one name in `toNetwork()`. It's the same idea as a JPA entity whose `@Id` must stay the same across two aggregates if you want them to be "the same thing".
- **Remember: give keyboard users a second path instead of nesting tab stops.** Batch bands sit inside a pipe, which is already a roving-tabindex item. Making every band focusable would mean tab stops inside tab stops. Instead, the map gets a key (`B` cycles through a pipe's batches) and the table gets real buttons.
- **TypeScript note:** `const holdsFollowed = followed !== null && …; holdsFollowed && followed.name` type-checks because TS 4.4+ narrows through an *aliased condition* (a `const` boolean that holds a null check).
- Docs: https://www.typescriptlang.org/docs/handbook/release-notes/typescript-4-4.html#control-flow-analysis-of-aliased-conditions-and-discriminants
