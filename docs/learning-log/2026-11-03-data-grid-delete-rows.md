## 2026-11-03 — DataGrid delete rows (F4)

- **Built:** `editing.allowDelete` adds **Delete N rows** to the edit-mode toolbar. It acts on the rows in the selected range, skipping locked ones. Deleted rows stay on screen (struck through, muted, red rail, "Deleted," for screen readers) until Save sends `{ op: 'delete', id, version }`. The button becomes **Restore N rows** when they're all deleted, and Ctrl+Z works too. Contract, docs (`docs/data-grid-editing.md`) and the Editable story updated.
- **Remember: reuse the state you have instead of adding a parallel one.** A delete is just a draft value, `__deleted: true`, on the row. Undo/redo, "unsaved changes", the Save bar, failed-save recovery and `beforeunload` all work with no new code. Only three places needed to learn about it: `countChanges` (a deleted row is 1 change), `toChangeSet` (emit `delete`, or nothing for an unsaved new row) and the row's look.
- **Remember: growing a discriminated union is a breaking change.** Adding `| { op: 'delete' }` to `ChangeSetOperation` makes every exhaustive `switch (op.op)` in apps fail to compile until it handles deletes. That's the point: the compiler finds every place to update. It's opt-in (`allowDelete`), so apps that never delete never receive one.
- **Remember (the prediction): don't take the browser's shortcuts.** Excel deletes rows with Ctrl+−, but in a browser that's zoom out. A grid that `preventDefault`s it breaks zoom for low-vision users, right where they need it (WCAG 1.4.4). So deleting is a visible button, reachable with Shift+Tab, with no shortcut.
